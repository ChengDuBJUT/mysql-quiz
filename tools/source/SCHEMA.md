每章输出一个 JSON 文件 `tools/source/chNN.json`（NN = 01..07），UTF-8，**不要 BOM**。严格遵循下面结构，不要加额外顶层字段。

## 硬性要求

1. **知识点必须来自 PPT 原文**，term/desc/summary 不得凭空编造。desc 控制在 80 字内，信息密度高。
2. **page / pageRange 用 `<!-- Slide N -->` 的数字**，是该章 PPT 内部幻灯片序号（从 1 开始），不是全书页码。
3. **sections 覆盖该章所有小节**（原文里的 1.1 / 1.2 / 2.1 等编号），每节 points 3-8 条。
4. **题目数量（扩题版，重点）**：以题代知识点。每章题量按知识点密度定，**最少不少于 45 题**，具体目标见下表：

| 章 | 知识点数 | 目标题量 |
|---|---|---|
| 1 | ~126 | ≥100 |
| 2 | ~105 | ≥85 |
| 3 | ~105 | ≥85 |
| 4 | ~96 | ≥80 |
| 5 | ~61 | ≥55 |
| 6 | ~51 | ≥45 |
| 7 | ~75 | ≥65 |

   覆盖要求（硬性）：
   - **每个 section 至少 4 题**；
   - **每个 point（知识点）至少被 1 道题覆盖**（一题可以覆盖同一小节里 1-2 个紧密关联的点，但 analysis 里要写清考的是哪个点）；
   - 题干不要重复：同一知识点若有第二题，必须换角度（如从「是什么」换到「怎么用 / 错在哪 / 计算结果」）。
5. **题型配比**：单选约 65%，填空约 35%。单选一律 4 个选项。可出这些角度：概念辨析、细节记忆、正误判断（用 4 选项包装，如「下列说法正确的是」）、SQL 语法、代码结果、场景应用。
6. **题目答案必须能在 PPT 原文找到依据**，analysis 写明页码依据。禁止出 PPT 里没有的超纲题。
7. **选项格式**：字符串数组，每项以 `A. ` / `B. ` / `C. ` / `D. ` 开头，内容要有实质区分度；干扰项要像真的（常见误解），不要用「以上都对」「以上都不对」凑数。
8. **填空题 answer 是数组**，第一个是标准答案，后面是等价写法（大小写变体、中文/英文标点、带不带引号等）；`answerText` 与第一个一致。答案要短（1-2 个词），不要出整句填空。
9. **id 命名**：`ch{章号}-ppt-s{两位序号}`（单选）、`ch{章号}-ppt-b{两位序号}`（填空），例如 `ch3-ppt-s01`、`ch3-ppt-b01`。**扩题时保留已有题目的 id 和内容不动，新题从现有最大序号 +1 往后连续编号**，不要与已有 id 冲突。
10. 输出 JSON 必须能被 `json.load()` 解析，不要尾逗号，不要注释，不要 Markdown 代码块包裹。

## 扩题工作流（本次任务）

1. 读现有 `tools/source/chNN.json`，记下已有哪些 section/point 有题、已有单选/填空的最大序号。
2. 对照该章所有 section 与 point，找出**没有题覆盖的点和题量不足 4 题的小节**。
3. 保留全部原题（id、内容、顺序都不动），在 `questions` 数组末尾追加新题，直到满足上表题量下限与覆盖要求。
4. 新题 id 从已有最大序号 +1 开始连续编号；单选与填空分别计数。
5. 最后自查：题量达标、每个 section ≥4 题、每个 point 至少 1 题、答案字母都在选项内、JSON 可解析。
